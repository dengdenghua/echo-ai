# Evidence graph and personal memory

The local workbench uses `data_dir/knowledge-graph.sqlite3` as a separate sidecar. Its nodes, edges, import fingerprints, memories and memory links are durable SQLite records. Project payloads and revisions remain in `workbench.sqlite3`.

Configured `knowledge_catalogs` entries have `catalog`, `audit` and `topic`. Paths are supplied by the local operator, never by a tool call. `optics_sync_graph` verifies the catalog SHA-256 against `audit.catalog_sha256`, links rule source IDs to reviewed audit records and checks source SHA identities against the current workbench index. This first importer accepts conditional, unadopted rules only. It refuses silent replacement of an imported batch with different content. It does not execute source files or read full models. A matching audit fingerprint establishes recorded provenance, not a new independent optical validation.

The catalog contains `round`, `rules`; each rule has `id`, `source_id`, `source_sha256`, `statement`, `location`, `conditions_and_missing_evidence`, `adoption_status: not_adopted`, `full_model_validated: false`. Audit records contain `id`, `sha256`, `read_scope`. A document indexed as `registered_full_text_review` additionally requires the matching audit record to contain boolean `full_document_read: true`; its explicit extent is retained in the source review. Full reading does not permit promotion to physical-model validation or adoption as a project threshold. Existing scoped records remain supported. Machine-extracted unread files are not graph facts. The visual graph displays sources, rules, topics and combined condition/verification-gap nodes; these are curated relationships, not automatic causal discoveries.

Memory categories are `user_preference`, `engineering_lesson`, `open_question`. Every record needs text, scope and provenance. Engineering lessons link existing rule nodes and stay `reviewed_conditional`. Exact repeated writes are idempotent. A document cannot authorize a user preference. The memory is external storage retrieved by tools; it does not change model weights.

Read tools: `optics_graph_stats`, `optics_search_graph`, `optics_graph_neighbors`, `optics_search_memory`. Write tools: `optics_sync_graph`, `optics_remember`. HTTP reads use `/api/graph/stats`, `/api/graph/search`, `/api/graph/node`, `/api/memory`; writes require the existing session token and origin checks. `#graph` opens the visual page.

For migration, stop the process using the private sidecar or use SQLite's backup API to make a consistent copy. Copy the sidecar to the new installation's configured data directory. Separately migrate the private source index and audited catalogs, update local configuration, and resync to refresh source locations. Do not publish private SQLite files, catalog content, memories or local configuration. Distribute this code, workflow Skill and synthetic tests. Reconnect the MCP process after updating its implementation so the client discovers the new tool list. An existing connection does not automatically acquire new tools.
