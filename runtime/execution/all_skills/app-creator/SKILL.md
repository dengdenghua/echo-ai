# 应用创建器

应用是用户打开后通过界面操作的工具，与被 AI 调用的技能和插件分别管理。创建应用不要求插件清单、Python 插件入口或技能包装。

## 生成

根据用户需求确定主要操作、输入、结果和数据保存方式。信息足够时直接制作；只询问会影响功能的缺失信息。默认在当前任务工作区的独立目录开发。

当前个人应用格式是可离线运行的单文件网页：应用目录包含 `app.json` 和 `index.html`。CSS、JavaScript、图标等放进 HTML 内部；不加载 CDN、外部脚本、远程接口或相对资源。应用运行在不具有宿主身份的隔离框架里，不能依赖 localStorage、宿主令牌或直接调用 Echo 后台 API。

需要持久保存时声明 `app.storage`，通过宿主注入的 `window.echo.storage` 保存 JSON 数据；同一用户、同一应用 ID 的更新版本共享数据。需要 AI、技能或插件工作时声明 `task.request`，通过 `window.echo.tasks.request` 请求用户核对后执行，使用 `tasks.get` 或 `tasks.wait` 获取进度和最终回答。实现这些功能前读取 [应用桥接接口](references/app-bridge.md)。仅声明所需权限；不需要宿主能力的应用继续使用空权限数组。

`app.json`：

```json
{
  "schema": "echo.app.v1",
  "id": "customer-tracker",
  "name": "客户跟进",
  "description": "维护客户和跟进事项",
  "version": "0.1.0",
  "entry": "index.html",
  "permissions": []
}
```

ID 使用小写字母开头的字母、数字、连字符或下划线，最多 64 字符。名称最多 120 字符，描述最多 1000 字符，版本为三个数字段。支持的权限仅 `app.storage` 和 `task.request`；声明权限不等于获得任意宿主接口的访问权。

## 验证与安装

验证页面的核心操作、空状态、输入错误、窄屏显示和数据导入导出。使用宿主存储时验证关闭重开、保存冲突和保存失败；使用任务接口时验证取消请求不执行任务、等待中不显示成功、失败或部分完成不当作成功、结果通过 textContent 等安全方式展示。用浏览器实际打开并操作，不能只凭 HTML 文件存在就宣布完成。

在用户要求创建并使用应用时，完成后调用宿主的 `deploy_website(local_dir=<应用目录>, label=<应用名称>)`。它会检查 `app.json`，复制应用快照并记录所属用户，生成的应用随即进入 HUB → 应用 → 我的应用。只有工具返回 `ok: true` 才报告已添加，返回错误则修复后重试。不要直接改部署清单或安装目录来绕过所属用户检查。

修改时保留同一应用 ID，增加版本号并再次部署。应用列表显示该 ID 最新的快照。交付名称、打开位置、完成的交互检查以及数据保存限制。当前流程为本机安装，不自动上传公网或发布市场。
