# 会话续接与删除错误反馈验证

日期：2026-09-26。

## OpenCode 会话续接

原因为纯对话回合使用身份级引擎目录，工具回合使用线程级引擎目录，两者共享 session.json 会话坐标，却读取不同的原生数据库。实际日志显示首轮 tool_free=true、后续 tool_free=false，随后出现会话不存在错误。

修正为两种模式使用同一个身份隔离的引擎数据库，线程仍各自保存会话坐标。仅在原生接口返回 404，且调用方提供可用于初始化新会话的 Echo 历史时恢复会话；认证、服务错误、记录损坏不触发重建，创建失败保留旧坐标。

- 后端相关测试：107 通过，含纯对话→工具→纯对话存储一致性、404 恢复、非 404 不重建、创建失败不覆盖旧坐标。
- 真实 OpenCode 进程隔离验证：重启及换模型后会话仍可读取；缺失会话可恢复。此项未发送模型请求。
- 重启后端后，在用户当前对话点击最后一条问题的重试：实际模型请求成功，事件记录 turn_completed/status=completed，页面显示回答并将前两次失败标为“先前尝试失败，后续已恢复”。

## 删除错误反馈

用户报错请求在日志中为 DELETE /api/threads/{id} → 409。只读检查确认目标仍是 Project OS 的绑定主会话。后台既有删除关联保护保留，未直接删除用户项目、群或聊天记录。

前端 API 客户端保留 HTTP 状态与结构化 detail，区分项目关联、群组关联、执行中、权限和目录校验失败；失败时恢复列表、给出原因。项目侧栏、普通侧栏、最近对话与移动抽屉均改为删除成功后才导航。

- 前端相关测试：61 通过，包含结构化错误解析、项目冲突回滚且不触发成功回调。
- TypeScript 检查通过，Python Ruff 检查通过。
- 后端与前端代理健康检查：HTTP 200。

边界：项目主会话仍受关联保护，需先处理项目及工作群关联后才能永久删除；此次未执行该数据删除。
