# 群聊与多人协作回归 · 2026-09-26

本轮使用隔离的完整 Echo 服务和 Chromium 独立用户上下文验证多人操作，没有用前端接口替身代替群聊后端。登录、权限、邀请、WebSocket、数据库和页面均走实际代码；项目规划使用固定的离线模型回复。

## 修复

1. 群聊 WebSocket 未协商认证子协议：服务端接受连接，Chromium 却拒绝握手并反复重连。现在回传非敏感的协议标记，测试断言协商结果。
2. 旧连接关闭或发送失败时，可能删掉同一成员的新连接并把其标为离线。清理逻辑现在检查连接实例是否仍为当前连接。
3. HTTP 消息、回应、置顶、批注和实时聊天落库后缺少可靠的成员刷新通知。统一发送群更新提示；通知失败不把已提交的写入变成失败响应，避免重复切换回应。
4. 前端无条件过滤 `thread:*` 群消息副本，导致另一位成员看不到已保存的发言。现在只有当前窗口确实已有对应原消息才去重。
5. 重连后重新读取批注、回应、置顶；已离开群聊的旧刷新请求不能覆盖新群数据。服务端通知先于提交响应到达时，按批注和回复 ID 去重。
6. 只读角色的输入、消息动作和批注编辑入口与服务器权限一致；修正四种语言的只读说明。
7. 实时消息使用服务端解析的成员显示名与真人来源，避免所有窗口都显示“我”。已有消息转项目记录时复用原始消息，保留作者并避免再次投影产生冲突。
8. 并行协作取消存在回调顺序竞争：一个取消回调做 I/O 时，其他工作线程还看不到父级取消。子 token 现在直接检查父 token，并增加阻塞回调的确定性回归用例。

## 复跑

在 `frontend` 目录运行：

```powershell
npm run e2e:collaboration
```

入口自动生成本次测试 JWT 密钥，使用 13220/18220 端口，创建 Alice、Bob、Viewer 和另一租户 Outsider，重置的状态仅位于仓库 `test-results/collaboration-state`。渠道配置也指向该隔离目录。需要已有项目依赖、Python 虚拟环境和 Playwright Chromium。

后端测试集及执行方式记录在结果 JSON 中。前端回归覆盖 collaboration/cowork/group、成员选择与 team join 相关测试；具体测试名保留在原始报告中。

## 本次验证边界

本轮验证的是同机独立浏览器用户与真实服务的协作链路。没有据此宣称真实模型答案质量、跨 NAS 设备长时间运行、百人并发、Safari/Firefox、语音视频和所有附件类型都已通过。发言策略、队列、取消、重试、项目抢占等还由后端自动测试覆盖，并非每项都有浏览器操作用例。

未重启生产服务、部署、提交或清理工作区既有改动。
