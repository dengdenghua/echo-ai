## 原有修复的复核

以下处理在本轮开始时已经存在，相关专项测试通过：

- `use_capability` 校验动作是否属于能力，内部派发复用权限、风险、审批和作用域检查。
- workflow 环境变量裁剪、工具风险按副作用 affinity 提升；网络权限和子代理工作目录由宿主约束。
- execute_skill 读取范围约束、命令参数化、Git 只读命令校验、媒体输出路径限制。
- Tentacle 控制权限、终端 WebSocket 子协议认证、无 owner 历史会话访问控制。
- Teams 签名及回传服务地址校验；其他渠道 webhook 凭证检查和常量时间比较。
- HTML/SVG/部署产物的隔离响应头、原始文件预览限制；通用安全响应头。
- 无密码登录不能被视为对外监听的安全鉴权；容器存储端口默认回环绑定。
- `e6ae6e80` 中的 Python 依赖和 GitHub Actions 修复、已跟踪根目录卫生。

`host.same_origin` 的远程工作台另有第一方来源校验，不把它等同于任意第三方插件可申请的权限；本轮没有移除第一方工作台所需权限。ComfyUI 本机原生界面位于独立端口，未按同源插件处理。

## 续修：部署、解压与 workflow 隔离

用户要求继续后补齐以下处理：

- **workflow**：每次执行只打包 worker/realm/protocol/types 四个无第三方依赖模块，使用私有临时目录，禁用 site/PYTHONPATH 注入。Linux bubblewrap 仅挂载 Python 标准库、系统动态库和只读代码包，隔离网络、用户及 PID 命名空间，不挂载项目、宿主 home、配置和凭证目录。worker 设置内存、文件大小、文件描述符、core dump 上限，退出或取消后清理临时包。
- **拒绝不安全回退**：production/shared/server/commercial 和显式严格沙箱模式缺少 bubblewrap 时拒绝派发；已安装但被内核禁止启动也不会改走直接进程。原有 AST 约束与宿主工具授权继续生效。本地不支持该后端的平台使用受限 DSL 兼容路径。
- **部署**：修正 Docker 宿主 8310 端口示例和测试，补上文档已引用的 `deploy/echo-ai.service`，提供专用账号、持久目录、只读系统目录、无额外能力、2G 内存上限及自动重启。
- **生产登录**：配置密码用户和强 JWT 密钥的普通账号可在生产环境正常认证。固定账号快捷入口和无密码开发登录仍只限开发/本地；`allow_any_username` 不绕过已有密码库。未配密码或签名密钥的生产登录拒绝服务。
- **模板安装**：旧金融模板已经只保留角色说明，完整角色包由云目录分发。安装先检查声明的所有技能，缺失就明确报错，不能生成看似成功但缺技能的角色；现有不完整或符号链接技能目录也拒绝复用。PVC 回归改用完整技能包夹具，另加缺失技能不留下半成品的回归，未伪造原版金融技能内容。
- **Electron 解压链**：通过 pnpm 的补丁和锁文件 hash 固定 `extract-zip@2.0.1` 修复。检查所有目录后才创建文件；检查链接最终目标，逐组件处理链接与 `..`，拒绝最终文件链接覆盖，普通文件删除旧目录项后独占创建。保留内部相对框架链接，限制链接文本大小。未添加 audit 忽略项。

公告依据：[CVE-2026-19693](https://github.com/advisories/GHSA-7pqw-9j4j-h8q3)、[CVE-2026-56876](https://github.com/advisories/GHSA-jmr9-qjv8-65gv)。本地补丁说明和维护条件见 [patch README](../../frontend/patches/README.md)。补丁后的原始版本扫描见 [audit JSON](security-frontend-audit-patched-2026-09-27.json)，仍为 2 high，生产依赖仍为 0。

## 未闭合项与边界

1. **本地 Windows/macOS workflow 兼容路径仍不是 OS 沙箱。** Linux 已有上述隔离和实测，生产/共享缺少该条件会拒绝 workflow；不能据此承诺任意平台的任意第三方 Python 都可安全执行。隔离不代替宿主对子任务及工具的授权，也不覆盖内核漏洞。
2. **完整金融技能包仍需通过角色目录安装。** 缺失依赖的旧模板现在报错，不能将测试夹具当成已补齐的金融技能；之前 5 个部署/模板检查失败已修正。
3. **版本扫描仍有 2 条 extract-zip 告警。** 本地补丁已覆盖公告攻击路径，等待上游正式修复版本后才能移除补丁并依靠升级消除扫描告警。解压目录仍须私有，不防御其他本机进程并发替换祖先目录的竞态。
4. 浏览器 bearer 兼容路径仍使用 sessionStorage。已隔离通用插件和产物，但尚未完成桌面/移动端到纯 HttpOnly cookie 的统一迁移，也未启用覆盖所有旧内联页面的严格 script-src 策略。
5. 撤销会阻止后续令牌验证，不主动断开已经建立的所有长连接；默认 TTL 调整不追溯缩短已签发令牌。限流按进程维护，多副本部署还需网关共享限流。
6. 第三方 MCP server、插件后端和整个供应链没有在本轮逐一审计；以上不构成完整渗透测试。未执行真实模型调用、发送外部消息或触碰用户项目数据来验证攻击。

非回环前后端分开部署时，显式设置 `ECHO_ALLOWED_ORIGINS` 为可信前端的完整 origin；不要通过通配允许来源恢复连接。后端源码变更需在服务下次启动时加载。
