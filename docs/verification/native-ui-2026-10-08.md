# Echo 原生交互卡片 · 2026-10-08

本批在原有对话中加入 `show_ui`，支持纯文字说明、方案对比表、需求表单和当前任务清单。现有 HTML/SVG 可视化保持独立，原生卡片不执行生成的 JavaScript。

## 交互与执行

- 模型按需读取 `visual_guidelines(module="ui")`。简短问题继续用原有问答；多个相关字段用表单；不同时重复展示两种问卷。
- 服务端验证版本、字段、唯一 ID、表格宽度与载荷边界。未知属性、隐藏动作和模型自填任务状态均被拒绝。
- 文档随工具参数保存；工具结果仅返回 `echo.ui.v1`、会话 ID 和校验状态，避免工具输出压缩损坏卡片，同时减少重复上下文。
- 流式参数中只有完整且有效的块可预览。表单必须等待成功结果，并匹配当前对话 ID，才允许操作。
- 表单点击后发送可见字段组成的普通消息，复用当前对话发言权限、工具权限与审批。提交表单不会直接邀请成员、执行工具或发布群消息。
- 显示“已收到”需要同 ID 的服务端用户消息；本地乐观消息不算回执。刷新后的人工重试沿用原消息 ID，由现有实时服务的持久化去重处理。
- 草稿保存在当前浏览器会话存储中，按后端地址、远程设备、账号、对话、工具调用及表单隔离。表单结构变更不沿用旧草稿。未识别账号或禁用存储时仅保存在内存中。
- 任务卡读取当前对话的服务端任务清单，显示“计划完成”，明确不等同于协作执行验收。

## 验证范围

通过：96 项后端测试、194 项前端测试、TypeScript 检查、相关文件 Ruff/ESLint 检查及生产构建。Chromium 原生卡片交互回归通过。生产构建仍提示既有 `liquid-glass.css` 的 `@import` 顺序问题，本批未改动该样式文件。

后端覆盖协议边界、私聊会话归属、大文档回执压缩、工具注册与角色可用性，以及原有视觉表达契约。前端覆盖流式预览、拒绝结果、跨对话隔离、账号/设备草稿隔离、发送回执与重试、现有发送链路，以及过程回放折叠时卡片可见性。

Chromium 浏览器测试使用实际 React 组件，验证必填项、对比筛选、动态追加内容、重复提交防护和 375px 窄屏；传输回执在该测试中受控模拟。真实模型自主选用卡片的概率、完整模型调用耗时尚未评测，不声称达到 OpenAI 模型训练层面的 Intelligent UI 能力。现阶段图表和自由交互继续使用 `show_visual`；任务卡不是群成员执行监控面板。

本批没有增加前端依赖、独立动作网关或数据库迁移。运行中的后端需重新加载工具注册；前端需加载新构建。
