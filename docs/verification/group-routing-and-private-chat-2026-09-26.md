# 群内分派、邀请审批与私聊隔离

日期：2026-09-26

## 修复

- 成员执行栏的跟进输入原先直接触发群聊 `composer:insert-mention` 并自动发送。现改为“打开私聊”：进入指定成员的独立对话，只填入草稿；“群聊草稿”明确提示发送后群成员可见。
- 私聊标记贯穿新建路由、第一轮状态切换、后端快照与历史加载。私聊不套用群协作人员预设，也不改变全局默认角色；顶部标明私聊对象。
- 群内 `call_agent` / `call_agent_parallel` 接入已有持久任务队列，约束为本群可执行成员，重复同任务请求复用任务。嵌套任务与组合工具同样校验群成员。
- 只有能力缺口才提交全局候选审批。提案包含现有成员、缺口理由、候选及拟承担任务；服务端只允许群管理者决策，同意后经既有邀请入口同步群/项目关联工作室并排队。拒绝不邀请、不执行，重试不会重复派发。
- 后台完成结果产生幂等回执；队长查询可以获取实际结果。验收区分排队与交付，支持动态工具名称。任务面板和成员执行栏读取持久结果，原主对话结束后仍可见。

## 验证

- 后端专项：75 passed、1 skipped（Windows 无法删除正在打开的 SQLite 文件场景）。覆盖排队、全批成员校验、嵌套边界、持久回执、邀请拒绝/同意/重复、审批权限、模型目录与执行。
- realtime 全集与新增私聊/交付用例：108 passed。包含私聊身份实际写入 ThreadStateStore、后续轮次保持身份、排队不能误算交付、历史交付不能充当当前轮结果。
- 前端工作栏、持久任务、私聊入口、审批弹窗：113 passed、2 skipped；`tsc --noEmit` 通过。
- 浏览器验证：成员执行栏出现“打开私聊”及“群聊草稿”；独立 Kane 草稿顶部显示私聊身份，刷新仍保留，未发送测试内容。原群聊执行栏可以显示已保存的 Kane 产品技术分析。
- 原群对话终止且后台队列无活跃任务后重启 8310 后端；启动成功，群协作接口返回 200。前端 3310 热更新已生效。

## 范围

未自动重发用户原来的研究任务，未撤回旧群消息，未邀请实际全局候选。验证使用隔离测试数据；浏览器验证仅打开草稿和查看已有结果。
