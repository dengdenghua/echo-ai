# 角色所需连接

角色可以声明完成其职责所必需的连接器及外部 MCP 名称。声明用于导入校验和角色详情中的准备检查，不安装服务、不授予权限，也不保证实际调用成功。

## Echo 角色

在 `profile.jsonc` 中声明：

```json
{
  "dependencies": {
    "connectors": ["feishu", "dingtalk"],
    "mcp_servers": ["research-db"]
  }
}
```

使用当前目录中的精确连接器 ID；名称相似的条目不会替代它。每类最多 64 项，ID 为 1–128 个字母、数字、下划线、点或连字符，以字母或数字开头。重复 ID 会合并。未声明依赖的旧角色保持原行为。

只声明必需的连接。不要在角色资料中填写 Token、请求头、服务地址或执行命令；凭据仍由既有连接管理流程保存。

## 导入 WorkBuddy 角色包

`.codebuddy-plugin/plugin.json` 支持以下依赖格式：

```json
{
  "name": "research",
  "dependencies": {
    "connectors": ["feishu"],
    "mcpServers": ["connections.json"]
  }
}
```

`mcpServers` 为包内相对文件路径，支持单个字符串或数组。未声明时兼容根目录的 `.mcp.json`。引用文件应含 `mcpServers` 对象：

```json
{"mcpServers": {"research-db": {"url": "https://example.invalid/mcp"}}}
```

导入只将服务器名称保存在角色依赖中，不复制连接凭据或自动执行 MCP 配置。路径越界、声明格式错误、引用文件缺失或 JSON 损坏会阻止导入，并在写入角色与技能之前报错。

## 在界面中检查

打开已安装角色的详情，展开技能检查，查看所需连接。连接器会显示未找到、需要安装、需要授权、未启用、需要连接、配置正常或状态待确认。

“管理连接”复用已有插件管理流程，只显示该条依赖。关闭窗口后自动重新检查；请求失败不会保留之前的成功提示。角色切换会取消旧检查。

外部 MCP 目前只显示声明及“尚未验证”提示，需要在插件设置中配置。连接器的“配置正常”也只表示本地配置和认证状态；仍需真实调用验证。

## 任务内修复与继续

实时对话在启动所选执行器之前，检查当前主角色声明的必需连接器。检查使用本轮经服务端验证的用户与租户身份；缺失、禁用、未授权、未连接或状态未知时，保留失败回执并停止启动执行器。

在失败回执中点击“修复所需连接”，通过已有连接管理完成配置，再重新检查。配置检查通过后，“继续当前任务”可用；点击后在原对话发起下一轮，服务端再次检查当前连接状态。关闭管理窗口不会自动执行任务，旧的失败记录也不会删除。

检查最多同时处理 4 个连接，总等待上限 15 秒。超时显示状态待确认。检查不代替工具实际运行时的权限校验，也不能证明外部服务正常。

Codex/OpenCode 保留已有执行器准备检查。账户、模型配置或程序不可用的结构化失败回执提供“打开模型设置”；配置后点击原回执的“重试”，在原任务重新进行服务端检查。

目前连接门禁覆盖实时对话主角色的必需连接器；外部 MCP、被委派子角色以及模型设置返回后的自动状态检查尚待统一接入。不要把角色详情或连接配置检查结果作为任务已成功运行的依据。
