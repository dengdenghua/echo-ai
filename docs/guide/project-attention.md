# 项目暂停与每日巡检

项目页面的执行请求会返回后台队列回执。回执表示请求已接收，最终项目状态仍以项目报告为准；刷新页面可以恢复运行状态，停止控制会取消排队或运行中的工作。

主动停止不消耗任务的失败重试额度。执行或质量检查发生真正错误时，仍消耗原有的有限重试次数。停止前已经返回的产物会保留为待检查状态，继续执行时先进行质量检查，不重复执行该任务。没有完成返回的产物不会作为交付保存。领取、退还次数和写回结果都受同一执行 claim 的事务检查保护，过期或已被替换的 worker 不能修改新 worker 的次数或产物。

服务启动时会补查项目，并在每天服务器本地时间 09:00 再巡检一次。巡检读取阻塞、逾期、待所有者验收和重启中断等已记录状态；它不会运行项目引擎、调用模型或自动授权后续执行。安静的项目不产生巡检提示。需要处理的项目每天记录一条带封印的时间线事件；重复启动和多个 worker 共用确定的事件 ID，不重复追加同一天的提示。

工作区每分钟读取 `/api/project-attention`。此接口需要与项目 API 相同的身份认证，返回当前租户中当前所有者的项目，管理员权限不会扩大个人通知的范围。已处理的项目不再出现在当日提示中。通知遵守现有总开关、暂停类通知开关和“仅在未聚焦时”设置，按所有者及日期去重；浏览器没有通知权限时不会将未显示的提示当作已送达。点击单个项目的提示会打开该项目，多个项目的提示会打开项目列表。

这些提示只反映已记录状态，不代表交付质量通过验收。服务器停机时不执行巡检；重启后补查。当前通知面向运行中的工作区和桌面客户端，外部远程通知 transport、长期执行授权和共享实时推送另有独立边界。
