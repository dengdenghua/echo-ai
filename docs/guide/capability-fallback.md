# 能力兜底

`find_capability` 是 Agent 的只读查找入口。现有插件、Skill 或工具没有匹配、
匹配不合适或执行失败时，Agent 按默认行为规则调用它；已有合适能力时不必调用。

```json
{
  "query": "装配体 STEP 导出",
  "reason": "failed",
  "failed_capabilities": ["已失败的工具名或插件 ID"],
  "external_query": "SolidWorks STEP export",
  "limit": 5
}
```

它检索本地插件、技能包和当前租户可见的注册工具，排除已失败的路径，返回最多十个候选。
匹配使用词项及中文双字片段，结果需要 Agent 判断适配性，并非语义匹配保证。
`registered` 只表示注册且未被基础开关禁用，不代表通过本轮权限、信任和审批检查。

本地候选仍不适合时，Agent 可按 `external_search.next_calls` 使用正常联网工具，
读取官网、官方文档及 GitHub 候选。只有显式提供公开的 `external_query` 才生成查询；
不把完整任务或原始错误自动发给搜索引擎。查找工具本身不联网、不执行候选、不安装，
返回的 `search_performed=local_only` 与真实执行范围一致。

后续读取、安装、启用和验证仍通过现有工具执行路径，遵守本轮工具范围及授权。
Agent 验证后继续原任务，避免对同一缺口重复搜索；无可行方案时报告具体阻碍。
这是一项带工具支持的默认行为，并非每次工具报错都强制触发的后台任务。

入口优先保留在原生工具目录和文本工具目录中，不新增常驻服务。
后端重新启动后注册入口；无需重新安装四个 CAD 插件。

## 规范与制度依据

能力兜底同时覆盖“能操作，但尚未确认应该按什么规范操作”的情况。
`purpose` 支持 `auto`（默认）、`capability`、`standards`、`office_policy`。
公差、国标、行标、明确标准编号自动进入标准查证；公司制度、审批流程、文件归档等进入办公制度查证。
关键词路由只是提示，可显式覆盖；普通插画任务不会因“画图”自动要求工程标准。

```json
{
  "query": "零件工程图的未注公差依据",
  "purpose": "standards",
  "standard_family": "GB",
  "external_query": "未注公差 标准 现行状态"
}
```

按需给出以下权威来源，不再把规范问题默认送到 GitHub：

| 范围 | 查证入口 |
| --- | --- |
| 国标、行标及地方标准线索 | [全国标准信息公共服务平台](https://std.samr.gov.cn/)、[行业标准](https://std.samr.gov.cn/hb/) |
| ISO | [ISO 标准目录](https://www.iso.org/standards.html) |
| ASME | [ASME Codes & Standards](https://www.asme.org/codes-standards) |
| IEC | [IEC Webstore](https://webstore.iec.ch/) |
| 中国政策依据 | [国务院政策文件库](https://sousuo.www.gov.cn/zcwjk/) |
| 档案管理 | [国家档案局行业标准](https://www.saac.gov.cn/daj/hybz/dabz_list.shtml) |

来源入口于 2026-09-25 核对；具体标准及条款需每个任务单独核实。
国家标准全文公开系统已按[官方通知](https://openstd.samr.gov.cn/bzgk/std/nd?no=83)并入全国标准信息公共服务平台。
`standard_family` 支持 `auto/GB/ISO/ASME/IEC`。未指定时的国内平台入口仅是查找起点，
不代表自动选择适用法域或采用 GB。其他地区和行业继续从相应发布机构/主管部门查证。

返回的 `requirements.status=not_verified` 明确表示尚未查证，附带版本、实施日期、现行/废止/替代关系、
适用范围、采用依据、条款/表号及来源日期等核对项目。首页、摘要、工具执行成功均不构成合规证据。
无法获得合法授权正文时列出待核实项，不猜公差数值，不声称已经符合标准。

办公与工程项目均可返回 `internal_document_calls`，通过可用的 `search_documents` 查企业/客户受控文件。
企业制度仍须确认版本、批准状态和适用范围；公共规范不能替代内部审批规则。
区分强制、推荐、合同采用和内部要求，存在冲突时记录并处理，不机械套用“最新版优先”。
交付物保留修订、来源和核查记录，区分草稿、审核、批准与发布，不代签、不冒充审批。

## 跨专业的标准化、通用性与复用

所有专业均优先复用已批准且适用的资产，采用适用标准、常用规格和成熟方案，确有缺口才定制。
这是默认选型偏好，不是“所有东西必须标准化”的硬限制，也不是特定品牌或供应商偏好。
功能、质量、安全、合规与项目约束始终是前提。

不同专业按自己的对象落实，例如：

| 专业 | 通用性与复用的落点 |
| --- | --- |
| 机械与结构 | 标准件、常用材料规格、通用接口、可维修和可替换结构 |
| 电子电气 | 常用器件系列、封装、接口与电源规格，核对参数、生命周期及替代条件 |
| 软件与数据 | 标准协议、数据格式、成熟维护的组件、可迁移接口，控制特殊依赖 |
| 光学与测试 | 适用的目录器件、接口、测量方法、校准与可追溯要求 |
| 办公与管理 | 受控模板、统一字段和命名、已批准流程、版本记录与可交接成果 |

`find_capability` 在所有查找模式下均返回 `selection_guidance`，供 Agent 比较候选方案。
按专业评估兼容性、互换性、可获取性、持续支持、维护交接、全生命周期成本及供应商锁定风险。
专业示例不是固定清单，不强行将机械规则套用到其他专业，也不因此每次都联网或新增审批。
采用依据、版本、已验证替代条件和待核实项应可追溯；选择定制方案时说明已有方案不适用的原因及代价。
