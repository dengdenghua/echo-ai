# Echo 设备执行与结果回收

任何运行 Echo 的在线设备都能作为执行节点。控制端保存项目身份、成员权限、任务、固定输入与交付；执行设备通过 HTTP 领取任务、下载输入，在私有目录内工作。电脑、NAS、服务器使用同一协议，不需要识别硬件品牌。

## 使用路径

1. 在控制端接入共享空间，取得已有的 Workspace ID。开启 `ECHO_FF_UI_REMOTE_WORKSPACE=1` 后，入口为项目目录 → 追加共享空间 / 同步 → 在其他设备执行任务。
2. 在控制端挂载项目。CD2、SMB、NFS 或其他工具均可，只要控制端 Echo 服务能读取实际目录。Windows 服务账户可能看不到登录用户的盘符，目录应以服务实际身份验证。
3. 配置执行节点允许处理的 `workspace_ids`，再启动该设备的 Echo 服务。执行节点不必再挂载源目录：每次领取后从控制端下载固定输入。旧版 `workspaces` 路径映射仍兼容，使用其中的项目 ID，路径不再用作此次执行的输入来源。
4. 界面选择共享项目、一个或多个设备及共同可用角色，提交文件任务。控制端先封存当前文件，再发布可领取任务；封存失败不发布。关闭窗口不取消服务端任务；选择多个设备后，失去租约的任务可由另一个设备使用相同输入重新执行。提交之后修改的项目文件需另建任务才会纳入执行。
5. 查看状态、下载交付，或应用到控制端可访问的项目目录。原文件相对执行时已经改变则报冲突，保留人工修改。

发起电脑能够关机的前提是控制端、项目存储与至少一个执行节点仍在线。把控制端放在即将关机的电脑上，或者只挂载远程文件而仍在本机运行 Agent，不能满足这个条件。

## 节点配置

沿用 [现有 Echo 部署](../deployment.md) 与认证体系，控制端启用身份认证。节点使用控制端签发的 operator/admin 身份令牌，普通用户仍需该共享空间 owner/editor 权限才能派发。跨设备 URL 使用 HTTPS；HTTP 只允许回环地址开发测试。

在执行设备创建配置，例如：

```json
{
  "controller_url": "https://echo-controller.example.org",
  "node_id": "office-device-a",
  "label": "办公室设备 A",
  "token_env": "ECHO_EXECUTION_NODE_TOKEN",
  "workspace_ids": ["<控制端的实际 Workspace ID>"],
  "roles": ["<本机已安装且加载的原生角色 ID>"]
}
```

模型配置和角色安装属于执行设备自身；启动时校验角色确实已加载、使用 Echo 原生引擎，以及项目授权列表有效。角色 ID 不是显示名称。外部 Codex/OpenCode 引擎不接受这里的文件任务派发，因为此入口依赖原生工具执行器的强制允许列表。

通过服务环境设置 `ECHO_EXECUTION_NODE_CONFIG` 为上述 JSON 的绝对路径，`ECHO_EXECUTION_NODE_TOKEN` 为令牌。令牌不写入配置、工作目录或任务记录；令牌过期/撤销后领取和续期会失败，需要更新服务环境。随后按现有方式运行 `echo-ai serve --config config.yaml`。不配置该变量时不启动节点轮询。配置错误会拒绝启动，而不是虚报设备在线。

节点只向控制端发起请求，无须新增节点监听端口。控制端和每个节点的数据目录各自持久化；**不要把控制端的 SQLite 数据库放到 SMB/NFS 供多个服务直接打开**。项目文件可挂载，任务数据库由单个控制端持有。

## 持久协议与恢复

设备任务使用已有 `collaboration_runs` 表及其事件记录，类型为 `execution_node`。设备广告只保存项目 ID、角色与状态，不把节点磁盘路径下发给其他节点。

- 提交键由组织、用户、request_id 派生；同键同请求返回原任务，同键不同内容拒绝。
- 控制端封存 ZIP_STORED 文件包和逐文件 SHA-256 清单，将包的摘要、字节数、文件数绑定到原任务。重复提交不重新封存，即使源目录已改变仍保留原版本。下载需有效设备身份、任务归属和领取代次；接管节点也下载这一份。下载中断最多重试三次，半包不交给 Agent。
- 领取使用数据库写事务；租约拥有者为节点 ID + 进程实例，领取代次 `attempt` 随每次重新执行增加。
- 心跳每 3 秒、租约 15 秒；丢失租约触发协作取消。续期和结果必须匹配仍有效的拥有者与代次，旧节点恢复后不能覆盖新结果。
- 空闲轮询每 5 秒；最多领取 3 次，耗尽后由轮询/查询协调为失败。恢复时间受网络、队列和执行设备负载影响，不承诺固定时延。
- 暂停撤销当前租约；接续启动新代次，从任务已固定的输入重新执行，不恢复原模型进程内存。取消为终态。
- 发送结果前保存交付 JSON 和文件内容；响应丢失时重发同一内容，控制端校验交付标识与摘要后幂等返回。
- 每次领取、心跳、交付都复核设备身份与任务提交者的共享空间权限。撤销写权限后不能继续续期或交付。
- 成功结果须确认输入包摘要，每份交付的文件基线必须与控制端保存的输入清单一致。不能把人工改动后的当前文件摘要伪装成原始基线来绕过冲突检查。旧版无固定输入的排队任务需重新提交；不会静默改用执行节点的当前目录。

`ExecutionRequest` 的宿主作用域也接入同一事件账本，记录 `engine_invocation`：引擎、设备、任务和父调用、完成/失败/取消。嵌套进入同一任务不会重复登记。界面可查当前服务的引擎调用并停止执行；取消经心跳传播，仍是协作取消。调用结束明确记录 `delivery_verified=false`，不能等同成果验收通过。ProjectOS、实时与协作队列仍分别拥有其领域计划和审核状态，没有宣称所有领域状态都已合并成一个调度器。

## 文件与副作用边界

当前设备入口处理文件读取、文本生成与编辑；宿主工具允许列表、文件根权限及禁用 shell/browser/network 的工具策略共同约束。模型服务仍由宿主配置调用。这不是 OS 容器沙箱，不执行任意脚本、CAD 进程、安装包、网络发布或付款操作，也不对这些外部副作用自动重放。

每个代次使用独立副本，默认排除 `.git`、依赖、`.env` 系列、常见凭证目录、链接及 reparse point。该过滤器不承诺识别任意名称的秘密。快照上限 5000 文件/512 MiB，交付最多 32 文件、单文件 8 MiB、总计 32 MiB；删除不传播。文件内容以 SHA-256 验证，应用前复核整个批次的基线和持久租约，写入单文件原子替换。多个文件的应用不是一个文件系统事务；中途 I/O 失败可能部分应用，重试跳过已经匹配的内容。

快照和交付目前保留在各自数据目录，未实现自动过期清理、断点续传、操作系统容器隔离、控制端高可用或全局文件锁。输入下载按 1 MiB 流式读写，不把完整大文件放入 JSON；下载校验包摘要、解包检查路径/数量/大小/逐文件摘要之后才运行 Agent。接管输入一致，但模型输出仍可能不同；这不是模型随机性或过程内存的确定性重放。目录的持续同步仍需使用原共享空间同步入口。

```text
.venv/Scripts/python.exe -m pytest tests/test_execution_inputs.py tests/test_execution_nodes.py tests/test_execution_lifecycle.py tests/test_collaboration_runs.py tests/test_execution_request.py tests/test_tool_effect_receipts.py -q
.venv/Scripts/python.exe -m tools.benchmarks.execution_node_recovery --output recovery-report.json
cd frontend
npx vitest run src/components/workspace/execution-nodes-dialog.test.tsx src/components/workspace/shared-spaces-dialog.test.tsx
```

覆盖独立数据库连接争领、真实子进程退出、旧代次恢复、暂停/取消、重试耗尽、权限撤销、真实 HTTP 丢响应、真实子 Agent bridge 与文件工具继承限制、摘要损坏、人工改文件冲突，以及界面重试不重复提交。模型输出使用确定性测试执行器，未消费模型服务，也未模拟成已经完成的实体双设备部署或 AX 同机对照跑分。

独立实验脚本启动隔离的回环 HTTP 控制端和两个 OS 工作进程，使用真实 15 秒租约、5 秒空闲轮询，终止工作进程 A 后由 B 接管；同时测试不同目录版本、过时结果、交付响应丢失与人工文件冲突，输出布尔验收项、恢复时间和提交次数。全部文件写入临时目录，不连接用户正在运行的服务。报告只反映同一物理主机上的受控故障，不是网络分区、双设备或 AX 对照成绩。
