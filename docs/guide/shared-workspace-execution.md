# Echo OS 共享工作空间

产品目标是自托管的组织工作空间。共享目录可在 NAS、其他电脑、文件服务器或挂载存储中；执行节点是任意具备所需能力并保持在线的 Echo OS 设备。设备品牌和型号不属于项目协议。

```mermaid
flowchart LR
  U[电脑 / 手机] --> E[选定的 Echo 运行端]
  E --> A[Agent 与项目执行]
  A --> M[运行端可访问的挂载目录]
  M --> S[共享项目文件]
  U --> R[查看日志和结果]
  E --> R
```

## 当前落地

- 沿用已有 Workspace 身份、成员权限、文件租约和存储适配器。
- CD2 或操作系统已经挂载的目录按 `local` 接入；这里的 local 指 **当前连接的 Echo 后端设备**，不是浏览器所在设备。
- NFS 使用执行端实际的 `mount_point`，不把 `nfs://` 地址当进程目录。
- SMB、WebDAV、SFTP、S3 地址用于存储访问；需要原生工具直接在该空间运行时，可以在 `mount_options.filesystem_path` 指定执行端已有的系统挂载目录。该字段不会传给存储协议驱动。
- `GET /api/workspaces/{id}/execution-directory` 沿用工作空间写成员权限，返回执行端目录及访问状态。接口仅探测，不创建缺失的挂载目录，不上传文件，不启动任务。
- 工作目录选择器选择共享空间时，先取得执行端验证后的目录，再走已有的目录绑定流程。已有会话的目录锁仍生效，需要切换时走新任务入口。
- 修复工作空间创建/查询响应的 `workspace` 包装，以及健康检查 `ok` 与前端 `healthy` 的对接。

入口仍遵守现有 `ui.remote_workspace` 功能开关。后端可通过 `ECHO_FF_UI_REMOTE_WORKSPACE=1` 启用。远端运行端连接继续使用现有远端后端配置；本轮没有开启网络端口或修改部署。

## 路径与执行位置

### 如何接入与选择

1. 在 **运行 Echo 后端的设备** 上，使用 CD2、系统 SMB/NFS 挂载或其他文件系统挂载工具，让项目成为可访问的目录。Echo 当前接入已有挂载，不会代装挂载驱动。
2. 点击会话输入框的项目目录 →「远程挂载」→「接入共享目录」。已有挂载选择「本地」，填写名称和执行端目录；保存时会检查目录连接。
3. 新任务直接点击该共享空间，就把共享目录作为项目工作目录。已有任务更换主目录仍走新任务入口。
4. 保留当前本地项目时，点击「追加共享空间 / 同步」，选择已接入的共享空间。关联会保存到任务，主目录不变；移除关联不删除任何文件。
5. 点击「预览同步」查看上传、下载、冲突和排除项，再点「同步无冲突文件」。这是用户触发的双向文件同步，不是后台持续同步。两个目录须同时能被执行端访问；不会从浏览器上传客户端磁盘。

同步通过 SHA-256 和上次成功同步的基线判断单边修改；双方都修改、首次同名内容不同、基线之后一边删除时保留冲突。删除不传播。预览后文件改变则拒绝旧预览。默认排除 `.git`、依赖目录、`.env` 系列、常见凭证目录和链接文件；单侧限制 5000 个文件、512 MiB。冲突文件需手动处理后再次预览，当前没有冲突编辑器或定时同步服务。

附加空间的同步操作在每次请求中复核任务归属、组织和共享空间写成员权限。关联本身不是任意路径授权，也不会改变任务的工具访问范围；通过同步进入当前项目的文件按当前项目原有权限处理。

同一个共享项目在不同执行设备上可能分别是 `Z:\team\project`、`/mnt/team/project`。项目的共享身份和成员权限应保持一致，但系统路径必须由执行端解释。浏览器和桌面客户端不能把自己的盘符直接当作另一台设备的路径。

前端关闭不应等于任务取消。只有在任务确实由另一台在线设备的 Echo 后端持有时，发起设备关机后它才能继续。挂载远程文件本身不会迁移本机正在执行的 Agent。

## 后续接续边界

设备任务入口现已接入节点身份、在线状态、按项目和角色选择、持久任务归属、租约代次及结果回收，见 [设备执行与结果回收](execution-nodes.md)。当前支持在独立副本中执行文件任务，掉线后以新代次重新运行；不迁移已有会话的模型进程，也不自动恢复任意外部副作用。控制端与执行设备仍必须保持在线。

设备任务现在由控制端在提交时固定输入，再传送给获准的执行设备；设备侧只需配置允许处理的 Workspace ID，不必再次挂载源目录。接管继续使用同一版输入，之后的项目修改须另建任务。这与直接在挂载目录工作、或者手动同步附加空间是不同入口。

目录探测证明当前可访问，不证明后续始终在线、可写或已完成云盘同步。共享文件写入应继续沿用文件版本核对和文件租约；Git、SQLite 和 CAD 引用文件还要按其自身并发与一致性要求处理。

当前已将同步、受控文件工具、人工保存与撤销接到同机跨进程文件锁，同步同时遵守工作空间持久租约。任务入口新增目录就绪检查，后台协作新增心跳及领取版本校验。准确的覆盖范围、故障验证及跨设备剩余工作见 [执行一致性改进](ax-runtime-hardening.md)。
