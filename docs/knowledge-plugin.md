# 知识库内置插件

知识库应用使用 `knowledge_storage`，由现有 PluginHub 管理。AI 与 OS 复用同一独立服务协议和进程管理实现，各自保留数据目录与身份边界。

## 使用与生命周期

打开知识库，选择“安装并启用”，添加授权目录并建立索引。TXT、Markdown、代码文本和文本层 PDF 支持本机全文检索，中文结果包含原文件来源。

“停用”停止本宿主的知识库进程，并撤销已注册及已缓存的搜索工具调用。“启动服务”用于恢复意外退出的服务。“更新组件”重新加载当前桌面包携带的组件版本，保留原启用状态。获得新组件版本需要升级桌面包；此入口不从任意地址下载程序。

“卸载并保留数据”移除插件安装状态，保留授权目录记录及索引。再次安装恢复原知识库。原始文档始终留在用户授权目录。插件卸载不会删除桌面包内的共享运行组件。

## 部署边界

- Windows 安装包携带 `resources/knowledge-storage/echo-storage.exe` 及其依赖，无需用户另装 Python。
- Linux 使用资源目录下 `knowledge-storage/bin/echo-storage` 的隔离环境，不使用 PATH 上同名的旧文件浏览服务。
- 数据写入宿主用户数据目录的 `knowledge-storage/`；程序目录与数据目录分离。
- 每个宿主使用独立随机回环端口、令牌、数据租约。浏览器只能通过宿主鉴权网关访问，无法取得服务令牌。
- 本机服务通信不使用系统代理、不跟随带令牌的重定向，也不依赖 HTTPS 证书环境。外部 HTTPS 的证书验证保持原有行为。
- 未安装或停用时，不自动拉起服务，不降级到未经授权的文件根目录。

## 验证范围

真实进程测试覆盖安装、中文索引、来源引用、授权目录范围、修改和删除后重建索引、停用撤销、升级、卸载重装、崩溃恢复、独占数据租约及双宿主隔离。

OCR、向量模型和云端问答需要单独配置；本轮不自动下载模型。中文短语补充检索使用授权来源内字面匹配，尚未完成大规模性能压测。公网与真机验收另行安排。
