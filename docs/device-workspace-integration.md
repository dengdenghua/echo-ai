# Echo OS / AI / Mobile 统一设备互联（2026-09-25）

## 本轮结果

本轮同时修改 OS、AI 和 Mobile。复用已有设备池、配对、手机同屏和远程桌面接收页，将原先分散的入口接到真实连接上。三项目分别维护提交；本验收不代表已经合并或发布。

| 项目 | 本轮接通内容 |
| --- | --- |
| OS | 设备面板、网络雷达、任务画中画设备菜单使用同一设备目录；按 deviceId 打开或恢复唯一手机窗口；最小化与手机画中画保留组件；传输队列独立于窗口 |
| AI | `/workspace/devices` 使用同一设备中心；手机同屏、键盘输入、文件收发、画中画；切换设备保留已打开会话；显示服务端共享传输记录 |
| Mobile | 沿用 `android.mirror_frame`、`android.mirror_control`、`android.exchange_files`；电脑远程桌面接收页新增 JPEG 格式，保留 H.264；离开页面取消订阅、清理回调 |

硬编码的 iPhone、电视候选和投屏成功提示已从相关 OS 入口移除。附近候选来自现有 Mobile UDP beacon（9528），仅用于发现提示；必须完成原有邀请配对才能操作，不使用 beacon 中的凭据。

## 如何连接

1. 选择一个设备中心。AI 已管理连接时，OS 复用 agent-shared coordinator；由原生 OS 管理连接时，OS 挂载 AI 兼容 `/api/tentacle/*` 接口。
2. AI 工作台指向该设备中心的后端并使用有效 operator 会话。两端必须读取同一个 coordinator，不能各自启动互不相关的设备池后期待自动合并。
3. OS 的设备连接面板生成邀请；手机、Android 模拟器或云手机使用邀请连接。电脑/虚拟机沿用设备客户端注册，在两端显示相同 ID 和已注册能力。手机按实际需要授权屏幕采集与无障碍。
4. 从 OS 雷达、设备面板或任务设备菜单点击“打开手机”；AI 从“设备互联”打开同一设备。OS 最小化后再次点击设备会恢复原窗口。
5. 上传可选择多个文件或拖入；手机“Echo 文件收发”内可打开、分享、保存。手机通过系统分享进入 Echo 收发目录后，电脑端可下载。上传暂停后可从发起窗口继续，也可在另一个 OS/AI 窗口选择原文件接续。
6. 反向观看电脑：手机打开“电脑远程桌面”，OS/AI 对该设备点击“共享电脑画面”，由浏览器选择来源窗口。接收页关闭、设备掉线或停止共享时终止发送。

生产远程连接沿用现有 WSS、邀请和鉴权配置；本轮未部署云服务器或公网中继。UDP 发现依赖局域网可达，跨网连接使用邀请地址；当前 appliance 部署的 host 网络可接收 UDP，其他容器网络应按部署环境配置。

## 协议与会话

- OS：`/api/appliance/device-link/devices/{id}/mirror/{operation}`。
- AI：`/api/tentacle/devices/{id}/mirror/{operation}`，OS 兼容路由和 OS 原生路由共享 coordinator。
- 操作：`frame`、`control`、`files`、`cast`、`transfers`。认证仍由所属路由提供。
- 网关合并同设备、同参数的并发截图，在当前连接内短暂复用结果并限制截图间隔；重连不复用旧连接画面。
- 文件使用原有分块、SHA-256、断点续传及幂等协议；`_transferId` 和 `_transferAttempt` 仅用于网关记录与接续所有权，不转发为手机工具参数。每次接续生成新的 attempt；活跃传输禁止其他窗口抢占，旧 attempt 的后续请求及状态报告不能覆盖新进度。
- 传输记录持久保存在运行时数据目录 `tentacle/transfers.sqlite3`（遵循 `ECHO_DATA_DIR` / `ECHO_HOME`）：最多 100 条、保留 24 小时。由单个 coordinator 持有；OS/AI 别名读取同一份记录。服务进程重启后，未完成记录标记为 interrupted，保留已确认的字节数与 SHA-256；45 秒没有进度的 running 记录也转为 interrupted。
- 电脑投屏会话绑定设备 ID、会话随机 ID 和当前 WebSocket。只有主动订阅 JPEG 的目标设备接收数据，不广播到其他设备。格式、大小、频率均受限。

## 当前边界

手机同屏仍是 JPEG 轮询；浏览器电脑投屏是低帧率、无音频、仅观看，不提供浏览器所选窗口的远程控制。保留已有 H.264 接收能力不等于所有电脑客户端已经提供可用的视频采集。

未完成文件的 File 对象保留在发起页面内存，关掉手机窗口不会中断上传。刷新、关闭整个页面或换用另一 OS/AI 窗口后，可对已暂停、失败、中断的服务端记录点击“选择原文件继续传输”；名称、大小和 SHA-256 一致才从手机确认的位置续传。下载恢复采用从头下载并重新校验，不宣称浏览器下载字节已经持久化。尚未开始的排队文件没有服务端记录，页面关闭后需要重新选择。服务器只保存元数据，不保存原文件；手机收发目录被清理或临时上传过期后，原断点可能不可用。文件范围是 Echo 收发目录，尚非全系统文件浏览或任意两台远程设备直接互传。

独立 AI/OS 设备中心的自动联合、全系统剪贴板、iPhone/电视接收端、云端部署和通用虚拟电脑远控不属于本轮已验收功能；不能据此宣称华为互联全部功能已追平。

本机验收证据：`E:/echo mobile/build/unified-proof/`（画面、哈希报告、OS/AI 截图、反向投屏报告），原生测试日志 `E:/echo mobile/build/unified-phone-final.txt` 与 `unified-receiver-live.txt`。证据不包含配对凭据。

## 2026-09-26：跨端任务工作区

三个项目本轮都已接线：OS 设备连接面板、AI `/workspace/devices` 内的“跨端任务”，以及 Mobile 设置 →“跨端任务”。支持选择目标设备、提交任务、查看具体执行计划、确认执行、暂停后续步骤、取消、继续、读取结果和移除已结束记录。

### 同一项任务如何流转

1. 手机通过已经配对的 WebSocket 提交任务，或 OS/AI 通过已有登录会话提交。客户端重试相同请求使用原任务 ID，避免丢失响应后重复创建。
2. 设备中心复用当前运行时规划器生成最多 32 个步骤；没有配置规划器、计划为空或操作未声明时明确报错，不显示虚假的执行成功。
3. 计划先显示给用户。审批绑定该计划、目标设备、当前步骤和待核对状态的 revision；过期页面不能确认另一份计划。动作授权精确绑定参数，原有设备约束继续生效。
4. 复用 ProcedureExecutor 逐步执行，并持久保存结果和下一步位置。浏览器页面关闭不取消服务端工作。暂停或取消会阻止后续步骤，当前已经发出的操作仍需等待设备结果。
5. 服务重启后恢复记录。已确认成功的步骤不会重复执行；若上一步因断连、超时或重启而结果不明，必须在目标设备核对。确认已完成后跳过该步骤继续；未完成则取消后重新规划，不自动重放可能产生副作用的动作。
6. 其他已登录 OS/AI 页面可查询并接续同一任务；手机重连后从设备中心重新取回相关任务。结果列表显示最近三步，`get` 接口可读取全部已保存步骤结果。

### 接口、权限与部署

- OS HTTP：`POST /api/appliance/device-link/task-workspace/{command}`；AI 与 OS 兼容路由：`POST /api/tentacle/task-workspace/{command}`。
- Mobile：`task/workspace/{command}` JSON-RPC，经已认证的设备连接发送；来源身份取自绑定连接，不信任请求里声称的来源。
- command：`devices/list/submit/get/approve/pause/resume/cancel/remove`。既有旧版 `/task` 与 `task/execute` 兼容入口仍保留；新三端界面使用统一工作区协议。
- 手机可看本机相关任务；操作其他设备仍需要现有 `ECHO_DEVICE_PEER_GRANTS` 定向工具授权。计划生成后、开始执行时及每个步骤前都会检查授权；配对本身不授予任意跨设备控制权。
- 状态目录：`<运行时数据目录>/tentacle/task-workspace/`，含任务元数据及 `procedures/` 原子检查点。云主机或容器部署应持久挂载该运行时数据目录，并保持 OS/AI/Mobile 指向同一设备中心；两个独立中心不会自动同步。单中心最多保留 100 条任务，列表返回最近 50 条；完成后可移除记录释放空间。
- 复用已有后台运行时与 WSS/Tailnet 接入。此次没有新购、登录或部署公网云服务器，也不声称实现任意云主机自动迁移。
