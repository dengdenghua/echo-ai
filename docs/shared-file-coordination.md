# 同机共享文件写入协调

调用 `coordinate_file_mutations` 的写入入口默认使用同一操作系统用户的
`~/.echo/coordination/file-locks-v1`。项目目录、`ECHO_HOME`、`ECHO_DATA_DIR`
各自独立，文件锁命名空间仍一致。因此两个已升级的 AI 实例写同一规范化路径时，
后进入者会得到 `FileCoordinationConflict`，在取得锁之前不会写文件。
文件锁由操作系统持有；进程退出或崩溃后自动释放，不依赖 PID 文件或人工删锁。

需要指定公共锁目录时，设置 `ECHO_FILE_LOCK_DIR` 为绝对路径；所有参与同一
共享文件写入的实例必须使用相同目录。若启动器重定向 `HOME/USERPROFILE`，
也必须显式指定相同的 `ECHO_FILE_LOCK_DIR`。空字符串和相对目录会明确失败。
目录不可用或锁获取失败时拒绝写入，不降级为无锁执行。

文件锁只协调使用这个入口的、同机且共享锁目录的写入者。其他编辑器、旧版本
运行时、尚未使用此入口的 OS 写入链、独立操作系统用户以及其他电脑不在此边界内。
本次未把 AI 的文件同步整套功能移植到 OS，也没有修改原项目。
所有参与协作的实例需要升级并重启，旧锁目录不会在运行中迁移。

锁键使用解析符号链接后的规范化绝对路径；不同硬链接或网络映射路径仍可能
指向同一文件但产生不同键。跨主机目录需规定单一写入所有者或使用服务器侧
锁协议。进程锁也不替代断电耐久性、`fsync` 成功确认及数据恢复验收。

复核：`python -B -m pytest -q -p no:cacheprovider tests/test_file_coordination.py`
包含不同 `ECHO_HOME/ECHO_DATA_DIR` 的真实进程竞争、持锁进程退出后恢复、
不可用锁目录拒绝写入，以及线程、异步任务和目录同步批量写入检查。
